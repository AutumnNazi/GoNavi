# GoNavi 远程背景图库设计

## 状态与已确认范围

- 日期：2026-10-16；基础分支：dev。
- 用户已确认：图片托管 BeroHost；选择后下载并保存用户电脑；不将背景图片打包进安装包或提交到代码仓库；保留个人上传与离线使用。
- 候选范围：现有鲸鱼娘 A/B；GLM 娘立绘、书房横版；文心娘、JEV 娘、混元娘、MiniMax 娘立绘。
- 许可未明确的素材不上传、不在公开图库中上架；候选名单不等于发布许可。
- 用户已于 2026-10-16 确认实施及非商业用途；首批鲸鱼娘 A/B 后，已批准并部署 Pixiv 对应原版 GLM 立绘、文心轮椅版与 MiniMax。GLM 镜像版、JEV、混元和书房横版不发布；不自动提交或推送代码。

## 目标与非目标

1. 移除前端对两张现有 WebP 的静态 import；最终 Git 工作树和前端构建产物不含背景图片、缩略图或编码后的图片副本。
2. 使用 Bero 静态目录分发已许可素材；客户端只在显式打开图库时请求目录/缩略图，在用户选择后下载原图。
3. 已下载背景重启、离线均可用；网络故障或新图片失败不清空旧背景。
4. 保留开启状态、透明度、拖拽位置、个人上传、跨窗口同步。
5. 不重写 Git 历史；旧提交中的已有图片不会因本次移除自动消失。
6. 不改动数据库、安全审计、AI 配置；不引入新 UI 或状态管理库。

## 方案选择

- 直接把 CSS 指向远端：安装包小，但离线/下载失败不可控，拒绝。
- 全部采用 IndexedDB Blob 缓存：桌面/Web 都在客户端落盘，但桌面应用数据目录迁移不能覆盖 WebView 数据，持久化/配额行为因容器而异，不作为桌面主方案。
- **推荐：桌面 Go 文件缓存 + Web 客户端缓存适配层。** 桌面原图保存到活动 GoNavi 数据根目录；Web 版保存到访问者浏览器 IndexedDB，而不是把服务器目录冒充用户电脑。二者共享目录契约和前端交互，分别测试。

## Bero 服务端

- 复用文档中的现有源站 https://origin-download.syngnat.top:8443 ，静态根目录 /srv/gonavi-downloads。
- 新增独立命名空间 /gonavi/backgrounds/v1/，不纳入现有 release generation 清理规则。
- /catalog.json：有限大小 JSON、schemaVersion=1、可缓存并重新验证；失败时客户端保留最近有效目录。
- /assets/<sha256>.<webp|png|jpg>：内容寻址不可变资源；原图、缩略图分别记录 hash/尺寸/字节数。
- /licenses/<sha256>.txt：可选公开许可文本。完整许可/署名也随已安装条目保存，离线可查看。
- 精确路径 allowlist、GET/HEAD、nosniff、正确 MIME、不可变资源长期缓存；不开放目录索引和上传。
- Web 客户端仅访问公开静态内容，按需开放无凭据 GET 的 CORS，不放开写接口。
- Nginx 仅新增图库 location；先备份现有片段，nginx -t 成功才 reload。不占用 80/443/2053，不改证书或其他服务。
- 图库发布与应用发版解耦：资源先上传到临时位置并校验，再原子落位；目录最后原子切换。失败保留上一版本。
- 代码仓库只保存 schema、发布脚本、许可核验记录和必要的元数据；发布图片来源于仓库外暂存目录。

## 目录契约与信任边界

每个可发布条目包含：稳定 id、版本、名称/多语言名称、fit(contain/cover)、原图与缩略图的相对路径、SHA-256、字节数、宽高、作者/来源/许可/完整署名。

- ID 只接受有限长度的小写字母数字连字符；路径由受控前缀和 SHA/扩展名构成。
- 不接受任意绝对 URL、查询参数、片段、反斜杠、编码后的路径穿越或自定义本地路径。
- 仅固定 HTTPS origin；拒绝跨域重定向、HTTPS 降级、凭据 URL。
- 目录限制条目数、JSON 字节数和字段长度；重复 ID、未知格式、缺少权利记录或 hash/尺寸非法使整个新目录校验失败，保留旧目录。
- 只支持静态 PNG/JPEG/WebP，不支持 SVG/HTML/脚本；限制原图大小（16 MiB；文心原版为11,254,649字节，24MP限制不变）与解码像素数量，缩略图独立小上限。
- SHA 校验用于文件完整性，不把同源目录中的 SHA 描述为独立签名或权利证明。

## 客户端下载与本地存储

### 桌面

- 新增 internal/backgroundgallery 领域包，负责目录验证、下载、安装状态、缓存校验、取消与本地资源读取。
- 根目录采用 appdata 的活动应用数据根目录下 background-gallery/v1；不使用 OS 临时缓存，不放到应用包或项目目录。
- 复用严格 TLS 的全局代理 HTTP 客户端；请求传 context，设置明确超时、字节上限与并发上限。
- 同目录临时文件流式下载并计算 hash；验证字节数、格式和尺寸后 sync/close，并用 appdata.AtomicReplaceFile 原子写入。
- 本地读取需确认普通文件、受控路径和完整性；拒绝符号链接/目录/路径穿越；损坏缓存视为不可用，不自动联网。
- 已安装条目的元数据、许可、原图一起提交安装状态，失败不暴露半安装资源。
- 服务由 App/runtime 持有，不新增全局可变 manager 注册表；绑定层保持参数校验/调用/QueryResult 收敛。
- 图片以同源只读资源路径提供，不返回磁盘绝对路径，不用大 Base64 RPC，不用随机端口的本机回环地址。
- 文件资源路由只注册于 Wails 与带宿主鉴权的 SharedRuntime，不注册到普通 Web server；资源 GET 本身不触发下载。
- 普通 Web RPC 必须在服务端明确拒绝桌面图库安装、读取、删除与本地状态方法，不能仅靠前端选择不同 adapter；不得因 App 方法反射导出而让浏览器用户操作服务器磁盘。原生分离窗口沿用 allowDesktopMethods 和宿主进程鉴权。

### 运行时能力矩阵

| 运行环境 | 权威识别来源 | 保存位置 | 资源访问 |
|---|---|---|---|
| Wails 主窗口（dev/production） | 宿主 Environment/buildType 能力信息 | 当前活动 GoNavi 数据根目录 | Wails 同源受限资源路由 |
| 原生分离窗口 | 宿主注入 desktop-detached 与现有分离窗口桥接 | 与父窗口同一份 Go 缓存 | 经已鉴权的父窗口同源代理 |
| 普通 Web 浏览器 | 显式 web buildType | 当前访问者的 IndexedDB | 内存 Object URL |
| 尚未识别/能力不满足 | 默认拒绝图库下载 | 不降级到其他设备 | 提示不可用，保留现有设置和个人上传 |

不能仅凭 window.go、HTTP URL 或桥接函数存在来识别桌面。客户端识别不是服务端授权；RPC 拒绝表与资源路由必须独立生效。不得持久化分离窗口的随机父服务端口、绝对 URL 或会话 token。

### Web

- 图片保存访问者浏览器的 IndexedDB（Blob + 校验后的条目元数据）；应用设置仍只保存 ID/版本等小信息。
- 使用固定 Bero origin 的公开 CORS 资源，credentials=omit；完整性/格式/大小限制与桌面一致。
- 下载前检查 crypto.subtle SHA-256、IndexedDB 事务与所需图片解码能力。Bero 使用 HTTPS 不等于 Web 应用自身处于安全上下文；HTTP 非 localhost 页面可能没有 crypto.subtle。
- 首版不引入散列降级算法。缺少能力时给出明确的环境不支持提示，保持已有设置、个人上传和当前背景，不跳过校验、不转而存到服务器。CORS 错误、crypto 缺失、IDB 被禁用及配额不足均有反向测试。
- 下载成功并完成持久化事务后才切换背景；Object URL 仅内存使用，及时 revoke，不写入持久化设置。
- 存储不可用/配额不足时明确失败并保留旧背景；不声称刷新/清理网站数据后仍永久存在。
- 服务器端下载缓存不是用户电脑缓存，不以此替代 Web 实现。

## 前端交互与迁移

- 新增背景图库模块/hook/cache adapter，沿用 React、antd、Zustand；不扩张根 store.ts。
- 图库只在用户打开背景设置/图库时刷新；滚动可见缩略图按需加载；启动渲染只查本地，不联网。
- 卡片状态：未下载、下载中（进度/取消）、已下载、失败可重试；授权未明确的候选不提供线上下载入口。
- 用户选择后下载并校验，最后才提交选择；取消、关闭面板、切换到其他图或个人上传会使旧请求失效，迟到结果不能覆盖新选择。
- 下载/存储失败不清空旧背景、位置、透明度或开启偏好。
- 保留 whale-maid-a / whale-maid-b ID，兼容旧设置；旧选择缺少缓存时用普通主题并提示下载，不自动联网、不抹掉选择。
- 关闭背景不删除已下载资源，重新开启不联网；删除缓存需显式操作，不能静默驱逐当前选中图。
- 保留个人上传现有行为，不把任意远程 URL 塞进上传图片数据结构。
- 授权说明按当前条目展示；离线可读。不能将所有新角色归到鲸鱼娘许可。
- 所有新文案同步六种语言目录；生成绑定和语言压缩包走正式生成流程，不手改生成文件。

## 实施顺序与改动边界

1. 先建立测试：目录校验/下载失败/持久化/离线/选图竞态。
2. 领域下载与存储、薄绑定、同源路由；前端 cache adapter 与异步选择。
3. 图库 UI、个人上传兼容、旧 ID 迁移；先在仓库外保存原图、SHA-256、来源/许可和恢复说明并验证副本，再删除现有图片 import 和受跟踪的背景二进制，仅保留许可文本。重新构建检查残留静态图片与内联编码，恢复材料不得进入构建输入。
4. 发布工具/Nginx 片段、资源许可清单；经许可 gate 后再发布合法素材，不发布待授权图。
5. 自动测试、构建产物检查、真实下载/离线重启/失败不覆盖验证。
6. 不提交、不推送、不创建 PR，除非用户另行要求。保留现有 models.ts、go.mod、catalog.zip 等其他未提交改动，不将其当作可覆盖文件。

## 验收

- Git 工作树及安装包不含实际背景原图/缩略图/编码副本；目录 metadata 和许可文字允许存在。
- 没打开图库、不选图片时不下载远程原图；下载过的图重启与离线可用。
- 明确可取消进度；离线、404、超时、错 hash、过大、非法 MIME、损坏缓存、存储失败均保留旧选择。
- 服务端/客户端越权 URL、路径穿越、符号链接、重定向、重复 ID 等测试通过。
- Web 用户的资源存在其浏览器而非仅服务器；桌面主窗口和分离窗口均能读本地资源。
- 现有个人上传、关闭/开启、透明度/拖拽位置和六语言文本不回归。
- Bero 修改前后均可验证既有 /healthz 和 release/brand 资源未受影响；图库资源 HEAD/GET、hash、MIME、缓存/CORS 合同正确。
- 发布清单仅含审核通过的五张图片；JEV、混元、GLM书房横版及版本来源未核实的GLM镜像保持缺席，不把证据尚未核实表述为必须额外取得授权。

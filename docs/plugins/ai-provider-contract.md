# Plugin AI Providers: text, tool and image streaming v1

This slice connects native plugins to the real GoNavi Provider interface, saved provider settings, desktop/CLI Agent bindings, and explicit health checks. It supports genuine incremental text/reasoning, complete tool calls and bounded image input. It does not add opaque cross-turn upstream state, arbitrary host access, global factory registration, automatic provider fallback, or automatic replay after an uncertain plugin call. Preserve hosted built-in provider restrictions and all existing providers.

## Declaration and identity

Explicit permission `ai.providers`. Optional `contributes.aiProviders` has at most 8 entries:

`{id,name,command,models:[{id,name,contextWindow,maxOutputTokens}],supportsTools:boolean,supportsImages:boolean}`.

Provider id: lowercase `^[a-z][a-z0-9_.-]{0,63}$`, unique across providers. Name: nonblank valid UTF-8 <=256 bytes/no NUL. Command: actual declared backend command; backend mandatory. Models: 1..32, unique nonblank ASCII IDs `^[A-Za-z0-9][A-Za-z0-9_.:/@+-]{0,127}$`, names nonblank valid UTF-8 <=256/no NUL; contextWindow 1024..262144; maxOutputTokens 1..65536 and <=contextWindow. Both capability booleans are required. `supportsImages` opts the provider into bounded image parts; a provider that leaves it false rejects every image before RPC. Omitted, null, duplicated/escaped-alias/unknown/case-mismatched required declaration keys fail closed consistently. Model lists are static declarations, not implicit network discovery.

Type is exact `plugin:<pluginID>:<providerID>`. Parse before any trim/case normalization; malformed/case/whitespace namespace stays protected and never becomes custom/OpenAI/CLI. Public helpers `AIProviderType(pluginID string, declaration AIProvider) string` (invalid => empty), `ParseAIProviderType(value string)(pluginID,providerID string,ok bool)`, and namespace predicate may be added. Runtime `plugin.AIProvider` / `AIModel` declarations have matching independent SDK DTOs.

All provider-referenced commands are reserved, regardless of ai.tools. Generic runtime Invoke/InvokeGeneration, Agent ordinary tools, plugin UI/window command menus and direct resolves must deny/filter them. Preserve existing datasource reserved behavior and error sentinel; add AI-specific sentinel. Host-only `Manager.InvokeAIProviderGeneration(ctx,pluginID string,generation uint64,providerID,digest string,args json.RawMessage)(json.RawMessage,error)` resolves the actual command from the same durable admission snapshot, checks ai.providers/backend/gen/digest/state/owner/dependencies before and after RPC, and is NOT a Wails binding. A host-only read-only CheckAIProviderGeneration with the same identity arguments validates the same permission/dependency/owner/generation/digest conditions without starting code, issuing RPC, or taking invocation/response credits; the adapter uses it before/after every callback so buffered events cannot outlive dependency revocation.

## Per-instance factory and frozen provider binding

No mutable global provider registry. New provider-package `PluginFactory` is supplied two separate host callbacks: metadata snapshot (statuses, owned, safeMode) and current locally owned manager. Catalog reads never activate/read bodies/contact a model or keyring. Bind/New may boundedly wait only already-starting enabled local runtime; never take over another owner or silently enable/start code. Existing explicit desktop/CLI worker activation owns runtime startup.

Exact domain API: `PluginProviderSnapshot{Statuses []plugin.Status,Owned bool,SafeMode bool}`; `NewPluginFactory(catalogSource func(context.Context)(PluginProviderSnapshot,error),managerSource func(context.Context)(*plugin.Manager,error))*PluginFactory`; `Catalog(ctx)([]PluginProviderView,error)`; `Bind(ctx,ai.ProviderConfig)(json.RawMessage,error)` returns the flat frozen config; `Resolve(ctx,json.RawMessage)(Provider,error)`; `New(ctx,ai.ProviderConfig)(Provider,error)` binds then resolves; `ValidatePluginConfig(ai.ProviderConfig) error` performs static validation only. Host wraps the raw Bind bytes with existing NewProviderBinding (json.RawMessage preserves the JSON object). Coordinate any required signature change before callers edit.

Factory Catalog returns metadata views (type, pluginId, id, name, models, supportsTools, supportsImages as declared, version, digest, generation, available, state/reason). App.PluginAIProviders returns QueryResult around that metadata. Use package functions for factory/manager integration, not reflective App helpers. Direct/service/Agent plugin execution all respect Web denial, safe mode, current data root and owner lifecycle.

Factory Bind freezes selected config plus `_pluginRuntime` (pluginId, providerId, version, digest, generation) in a flat JSON envelope embedding ai.ProviderConfig. This envelope lives ONLY in the encrypted runharness.ProviderBinding; ordinary persisted ProviderConfig/Wails DTOs do not gain user-writable authority fields. Provider contextWindow/maxTokens remain top-level for existing context budgeting. Host creates pin before accepting a plugin-backed run; Resolve must use exact frozen pin, never re-read a current config or rebind a new generation. Reject plugin config claiming the reserved built-in provider ID BEFORE any Gateway token resolution. A restarted/disabled/updated/missing plugin fails old runs.

Service and CLI each get an instance-owned factory; retain builtin constructors/test seams. Desktop bind+resolve, non-Agent chat/inline completion, CLI bind+resolve, explicit AITestProvider, and model-list APIs must route plugin identities consistently. CLI InputBinder must pass its caller context; StartWorkers=false/readonly/queue-only cannot activate a runtime just to bind a plugin. Missing runtime means clear failure, not fallback. Do not expose function-valued lifecycle setters to Wails; use package configuration functions.

AIGetProviders/editor save/load retain raw plugin identity/model/secret reference even if disabled or absent. Save validation is static and must not execute plugin code. GetModels for plugin type uses declared static models only; never unknown-type OpenAI /models fallback or falsely report inactive provider healthy. AITestProvider performs a real bounded small Chat, reports model-response check kind, and does not equate Validate-only with connectivity. Existing config store deliberately clears Models/MaxTokens editor fields; respect this behavior rather than depending on them for persisted catalog/caps.

## Selected configuration and request boundary

Only the selected provider's baseUrl, apiKey, model and headers are projected to the plugin, plus request temperature/maxTokens and declared model limits as needed. Never send SecretRef/HasSecret, other provider records, DB credentials, CLIPath/CLIEnv or user environment. Keep secretstore/redacted-list and encrypted frozen binding behavior. On plugin saves, nil Headers means retain stored header secrets (and fail final validation if a forbidden field remains); an explicit empty object means clear. A nonempty header payload replaces the public-header snapshot while merging existing opaque secret headers, so editing redacted metadata does not silently drop authentication. Explicit new secret values override, and redacted empty values retain stored values. Any retained forbidden secret header must still fail final validation; use an explicit empty object to clear it. Do not silently filter forbidden secrets on nil/nonempty input. Apply the same explicit nil/empty distinction where foreign CLIEnv correction needs it, preserve empty snapshots through normalization, and validate the final resolved config before persistence. Ordinary providers retain their prior merge semantics. No request/header/body/error diagnostic logging.

Reject foreign transport settings BEFORE old normalization: nonempty APIFormat, CLIPath, CLIEnv, Effort/ThinkingIntensity, nonzero HeaderTimeoutSeconds, authMode outside empty/api-key. No silent downgrade/rewrite. The selected config's capability field is pinned to the declaration: a caller claim never widens or narrows what the plugin may receive. BaseURL may be empty for local providers; if present require bounded HTTP(S) URL with host, no userinfo/NUL. Selected API key <=16KiB UTF-8/no NUL. Headers <=32, token names <=128, values <=4096 UTF-8/no CRLF/NUL, aggregate<=16KiB, case-insensitive duplicate names rejected; reject Host, Content-Length, Connection, Transfer-Encoding, Upgrade and Proxy-Authorization. ProviderConfig ID/name/model are bounded; config model must match current declaration at Bind/use. Context override cannot exceed declared context; request output limit cannot exceed declared output limit. Saved missing/unsupported configs remain visible for explicit correction, never silently normalized to a builtin.

Requests: ai.Message roles system/user/assistant/tool, content/reasoning/tool_call_id/tool_calls, and optional `images` on user messages only. Images are bounded base64 `data:` URLs for `image/png`, `image/jpeg`, `image/webp` or `image/gif`: at most 4 per message, 4 MiB decoded each, 24 MiB encoded per request, with a 32 MiB JSON request ceiling for image-capable providers and the unchanged 512 KiB ceiling otherwise. Undeclared images, non-user images, remote URLs and malformed base64 are rejected instead of quietly dropped; the host never fetches an image URL. Also optional ai.Tool schemas. Request JSON depth<=32, nodes<=32768, messages<=512 and tool definitions<=128 (matching the current combined Agent catalog ceiling, not64). Model with supportsTools=false rejects nonempty tools or returned tool calls, not silently discarding them. Tool calls returned by plugin must be complete, valid object arguments, unique IDs, function type and names offered in the request; host approvals/policies still decide execution.

## Existing RPC wire, genuine pull streaming

Keep JSON-RPC plugin.invoke; no new stdout notifications. One completion uses host-generated 32 random bytes/raw base64url requestId, fresh per call. Args use `{protocolVersion:1,operation,providerId,requestId,...}`; only start/pull/cancel. Runtime checks providerId equals the privately selected declaration before forwarding. The SDK dispatcher multiplexes a bounded provider-ID->Generate registry, so multiple declarations may safely share one reserved command; every lookup/cancel is provider-bound.

- start adds selected `config` and `request`, returns `{accepted:true}` immediately after bounded admission. It MUST NOT wait for upstream completion.
- pull returns `{events:[...]}` and waits <=1s for data. Empty array means still pending, not an error or terminal. Caller cancellation stops the pull. One host consumer only; no retry/replay of a consumed or ambiguous batch.
- cancel returns `{ok:true}`, cancels the generation and clears buffered output. Unknown IDs create a bounded recent tombstone so a late start cannot revive canceled work.

Events have strictly contiguous positive sequence numbers and type:

- delta: nonempty content and/or reasoningContent strings.
- done: finishReason stop/tool_calls/length, optional COMPLETE toolCalls and usage.
- error: fixed safe code from canceled/deadline/unsupported/invalid_request/generation_failed/limit_exceeded; no arbitrary upstream error message.

Exactly one terminal event is required. Reject duplicate/out-of-order sequence, malformed fields/numbers, trailing events, silent EOF, or partial text without terminal. Delta content must not be treated as success after interruption. Tools are terminal snapshots, NOT incremental arguments (existing ProviderModelTurnAdapter replaces snapshots). Optional usage has bounded nonnegative integral promptTokens/completionTokens/totalTokens and optional cachedTokens; no NaN/unsafe integer/negative/null tricks.

Limits: one encoded event<=64KiB; pull encoded result<=128KiB and<=16 events; terminal complete tool-call JSON<=48KiB, <=64 calls, each ID/name<=128 and argument string<=32KiB; queue<=64 events/512KiB with cancellable producer backpressure; whole completion<=8MiB encoded events,<=65536 events,<=5min; active SDK workers<=16 with bounded recent tombstones. User/helper limits may be lower, never higher silently. Oversize fails explicitly, never truncates successful output.

Runtime uses per-instance shared AI request admission plus UNSETTLED RESPONSE credits, not request throttling alone: count72/s burst16; byte2MiB/s burst1MiB; <=8 unsettled AI replies and <=1MiB reserved reply bytes. Pull reserves128KiB+RPC framing allowance; start/cancel ACK reserves1KiB. Reserve at least2 slots for control and prioritize bounded cancel cleanup (<=250ms). A credit is released only on an actual validated reply or terminal transport/process shutdown—not caller cancellation. A definitely-unsent request may release immediately. Pending RPC entries enforce their individual response-size limit before delivery/settlement, including late replies; oversized responses fail closed. This bounds any1s AI reply window by carry+new admissions: <=96frames and<=4MiB, leaving room under existing256frames/s+8MiB/s total protection. All waits are outside manager locks and obey request+instance contexts. Ordinary Call/cancellation/tombstone semantics remain unchanged; use an optional bounded-RPC internal path with settlement callbacks and regression tests. SDK batch bounds remain mandatory. Admission/caller deadlines cancel only their operation; they are not evidence of a hung plugin. Each dispatched bounded pending reply instead owns its runtime watchdog until actual settlement/terminal shutdown, even after the caller returns. A real pending reply exceeding that independent execution budget still quarantines the offending generation; ordinary Call semantics remain unchanged. Normal and cancellation waiters have separate bounded capacity so normal saturation cannot consume the control queue.

## SDK lifecycle and host adapter

SDK dispatcher owns completion lifecycle, NEVER derives long-running worker from start/initialize RPC context (SDK cancels those on handler return). Provide explicit Close/Abort and a minimal server-close hook/root lifecycle integration that fires on ALL EOF/error/shutdown/parent-cancel exits BEFORE joins. Generator handler receives dispatcher-root child context and an Emit(delta) that blocks under queue backpressure and exits on cancel. Callback returns completion snapshot (finishReason/toolCalls/usage), dispatcher emits terminal. SDK catches callback failure, emits only safe error code, and does not free worker slot until worker actually exits—even after cancel—so uncooperative callbacks cannot create unbounded detached workers. Completed output retained only until consumed/canceled/expired; workers and retained session records are independently capped at16. A real dispatcher-owned 30s idle lease cancels jobs and clears queued output when valid pulls stop (empty pending pulls refresh it); do not rely on a later request to trigger expiration. Its janitor/timer stops with the dispatcher root. Close/Join is bounded to2s, while OnClose/Abort never joins. Roots close all sessions. Bounded tombstones, no start replay. One instance may serve a declared command; runtime limiter is shared across all provider commands.

Provider adapter implements Chat and ChatStream over the SAME completion stream. Chat aggregates; ChatStream invokes callbacks incrementally and never after return. Defer bounded cancel on every exit, including failed start/parse/budget/context/digest change. Capture immutable manager/pin/config for call; recheck every RPC and before callback, no fresh-generation reconnect. Complete explicit caller cancellation preserves ctx.Err; all other plugin failures return safe NON-RETRYABLE provider error without raw message/net.Error/EOF/HTTP5xx unwrap. Prove runharness.IsRetryableModelError=false and actual Harness failure has no automatic replay. Output length terminal maps to ai.OutputLimitError only when ReportOutputLimit is requested; known partial output remains useful for explicit continuation, not transport retry.

No SessionStreamProvider/SessionChatProvider opaque state v1. Native trusted code is not an OS sandbox; manifest/caps cannot prove malicious code safety.

## UI, examples, verification

Separate dynamic provider catalog/overlay and small plugin configuration components/helpers; do not grow oversized roots. Existing builtin presets/editor semantics stay unchanged. Missing/disabled/malformed plugin configs retain identity and secrets and show unavailable, not custom/OpenAI fallback. Provider-owned static model selector/caps; hidden unsupported fields retained/rejected until explicit correction. Catalog no activation/model request; testing is explicit and uses secret-preserving editor behavior. Clear/fence stale discovery/test results on disable/remove/update/root change. All strings in six languages; genuine Wails generation only.

Public Go/TS declaration and streaming dispatcher helpers, plus independently built native HTTP-compatible example translating real bounded SSE text/reasoning/toolcalls/usage into this protocol. Example is a provider transport, not an invented model; use local httptest upstream in subprocess regressions, no production calls or credentials. Cover chunks arriving BEFORE generation completes, early cancel, stalled producer/consumer, full queues, empty pulls, tool snapshots, output limit, unknown outcome/no replay, disable/update/gen changes, reserved command bypass, frozen secrets/no disclosure, existing providers and static Skills/datasources.

Keep strict market publication parity and manual review of every version. No commits, pushes, new root dependencies, production deployment or live paid provider calls.

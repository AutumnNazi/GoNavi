# Plugin exporters: bounded snapshots and ordered streams v2

This slice adds real third-party export formats to already materialized query-result selected/page data. It is NOT query-all/table/database export, a streaming database cursor, a new database operation, a filesystem grant, or a CLI/Web execution mode. Existing builtin formats and their normal workflows remain unchanged. Trusted native processes are not an OS sandbox.

## Declaration and authority

Permission `data.export`; optional `contributes.exporters`, <=8 entries:
`{id,name,command,extension,contentType,streaming?}`; `streaming` is an optional boolean, absent means false.
ID lower64 `^[a-z][a-z0-9_.-]{0,63}$`, unique in exporters; name nonblank UTF-8 <=256/no NUL. Actual declared backend command and backend are mandatory. Extension has NO dot/path, lowercase ASCII alphanumeric 1..16; contentType is exact `(text|application)/[a-z0-9][a-z0-9.+-]{0,63}` without params/whitespace. All five identity fields are required; `streaming` is optional and must be a JSON boolean when present. Strict exact keys, unknown/case/duplicate/escaped duplicate/null rejection, runtime/market/SDK metadata parity. Independent contribution ID namespaces; shared commands are allowed if dispatcher routes exporterId.

Format identity is exact `plugin:<pluginID>:<exporterID>`. Parse before trim/lower/normalization; protected malformed/case/whitespace namespace never becomes xlsx/csv/another builtin. Runtime `Exporter` DTO and helpers `ExporterType(pluginID string, exporter Exporter) string`, `ParseExporterType(string)(pluginID,exporterID string,ok bool)`, protected namespace predicate. All exporter-referenced commands join the existing reserved union: generic Invoke/InvokeGeneration, MCP/Agent tools, UI/window command pickers/direct resolution deny them regardless of ai.tools.

Host-only `Manager.InvokeExporterGeneration(ctx context.Context, pluginID string, generation uint64, exporterID,digest string,args json.RawMessage)(json.RawMessage,error)` and `CheckExporterGeneration(ctx,pluginID,generation,exporterID,digest) error` use exact declared permission/backend/command, current owner/root/live enabled state, dependencies, generation and digest. Check performs no RPC/start/inflight admission. No implicit enable/start/reconnect/retry. Preserve ordinary datasource/AI provider admission and errors. A one-shot exporter receives one snapshot RPC; a streaming exporter receives `chunkCount` ordered chunk RPCs over the existing bounded stdio transport; no new notifications/sessions. Each render RPC has a 10s budget; host work after the picker has an overall 20s context budget. Do not apply a timeout while the user is still deciding in the OS dialog, but app/request cancellation remains active.

## Streaming exporters v2

A declaration with `"streaming": true` opts into the v2 chunk protocol; absent or false keeps the v1 one-shot contract. Streaming changes only how an already materialized selection is delivered to the plugin, not where it comes from: query-result selected/page remains the only UI route, and the same pin, permission, generation, digest and protected destination rules apply.

The host freezes the full selection and validates every row budget before the save picker, then writes chunks in order: up to 512 rows per chunk, zero-based `chunkIndex`, positive `chunkCount`, and `1 <= chunkCount <= 1<<20`. An empty selection still sends exactly one zero-row chunk so the plugin can emit a header or an explicitly empty document. Each request is `{protocolVersion:2,exporterId,columns,chunkIndex,chunkCount,rows}`. Columns repeat in every chunk. A chunk reply is `{protocolVersion:2,exporterId,chunkIndex,rowCount,text}` and must echo the exact exporter ID and chunk index; mismatches fail the whole export. Chunks are stateless and independently authorized, so the host may retry a chunk after a transport failure without replaying earlier chunks. The plugin owns headers, separators and footers by inspecting `chunkIndex`/`chunkCount`; the host never parses the document.

Each chunk envelope and reply must fit 512 KiB, and each chunk may contain at most 512 rows / 131072 cells. The total document has no row or cell cap because rows are frozen once and rendered in bounded pieces. Oversized rows or chunks fail explicitly; the host never truncates, splits a row, or silently falls back to a snapshot. Progress is reported per completed chunk. A failure while writing the atomic destination leaves the original target untouched; after replacement starts, errors are outcome-unknown as in v1.

## Public host integration

App.PluginExporters() exposes metadata only: `{items:[{format,pluginId,id,name,extension,contentType,streaming,version,digest,generation,available,state,reason?}],truncated?:true}`. No body/data/keyring/plugin activation. Deterministic catalog <=256 items/256KiB metadata, explicit truncated flag if capped. Metadata source is separate from owned runtime getter, as Skills/AI providers; Web plugin access/execution stays denied, safe mode/root changes/foreign owner fail closed. Do not expose manager/Check/Invoke as Wails methods.

ExportFileOptions adds `PluginExporter *dataexport.PluginExportSelection` (JSON `pluginExporter`), selection is `{digest:string,generation:uint64}`. These are expected snapshot fences, not client authority. Existing ExportDataWithOptions branches on RAW plugin namespace or nonnil pin BEFORE normalization. Plugin format without matching pin and builtin format with pin fail before picker/plugin. Existing legacy ExportData(pluginformat) without pin fails explicitly, not fallback.

ALL query/table/database/headless export entrypoints reject raw plugin formats or pins BEFORE normalization, DB acquisition/metadata/COUNT/query/writer creation. No plugin format may silently enter old default-xlsx or query/table path. A caller supplying materialized data directly may use the snapshot API; the UI v1 opt-in is query-result selected/page only. Do not infer safety from labels: current table-selected and table-page paths can reexecute SQL.

Allowed plugin options are Format, PluginExporter, Columns, JobID, TotalRowsHint/Known only. Reject CSV/XLSX/comment/SQL/DDL/dialect/target settings when nonzero on plugin branch; frontend explicitly projects minimal options after choosing plugin format instead of forwarding irrelevant builtin defaults. Do not run builtin option normalization first (it invents XLSX/SQL defaults). Source total-row hints do not imply full-database export; actual snapshot row count is authoritative.

## Domain API and snapshot fidelity

New code in internal/dataexport/plugin_*.go, no App/DB dependencies. APIs:
- `type PluginExportSelection struct {Digest string; Generation uint64}` with camel JSON tags.
- `PreparePluginExportSnapshot(ctx context.Context,data []map[string]any,columns,selected []string)(PluginExportSnapshot,error)`.
- `NewPluginExporter(ctx context.Context, manager *plugin.Manager,format string,pin PluginExportSelection)(*PluginExporter,error)`; constructor binds/checks current instance, never starts it.
- `Descriptor() plugin.Exporter`, `Check(ctx) error`, `Render(ctx,PluginExportSnapshot)([]byte,error)`. Render output is validated UTF-8 bytes, no path, no automatic replay.

Snapshot `{columns:[]string,rows:[][]PluginExportCell}` contains ONLY selected columns in exact user order and values from the supplied materialized rows. nil selected means all columns; explicit empty selection is invalid. Selected columns must be a unique subset of the source column list. No row-map extras, connection fields, SQL, filenames, data-root paths, credentials or unrelated source metadata. Source columns <=4096, selected columns1..256, rows0..4096, total cells<=16384, each name UTF-8/nonblank/no NUL <=1024, preserves significant spaces. Duplicate names/unknown selected names reject. UI must reject unsafe JS integer numbers before serializing; do not claim recovered precision that was already lost at a JS boundary.

Cell wire is a tagged union `{kind,value?}`, value is a STRING when present:
- missing/null: value omitted (missing map key is distinct from present nil).
- string: exact valid UTF-8 text, including empty/control/NUL data; no silent cleanup.
- boolean: value exactly true/false as text.
- number: exact valid JSON numeric lexeme <=256 bytes (validate lexical syntax without converting tagged values to JS Number; valid large exponents/json.Number are not machine floats); Go integer/json.Number values preserve digits, finite floats only; reject unsafe integral float64 values rather than claiming JS-safe precision. No NaN/Inf/leading-zero/invalid numeric text.
- json: bounded canonical JSON text for nested arrays/string-key maps; UseNumber/raw-number preservation, strict UTF-8/duplicates/unpaired-surrogate checks, no arbitrary structs/custom marshalers, cycles or unsupported values. time.Time may be projected explicitly as RFC3339Nano string; []byte as binary.
- binary: canonical standard-base64 text for actual nonnil Go []byte input (empty nonnil []byte yields empty binary). Nil Go maps/slices, including []byte(nil), are null; json.RawMessage is an explicit exception: nil/empty raw JSON is invalid. Existing frontend base64 strings stay strings; do not invent a binary type from content.
- Explicit json.RawMessage accepts any strict JSON value, including scalars, as a json cell; nested RawMessage is decoded with the same strict budget/UseNumber rules. Nested []byte/time.Time are rejected rather than implicitly converted; their binary/RFC3339Nano projections are top-cell rules only. Arbitrary pointers/structs/custom marshalers remain unsupported (no callback execution); known time.Time/json.RawMessage special cases are explicit.

Each string-valued cell <=128KiB, depth<=32 and nodes<=131072 for the FULL logical envelope, plus the overall512KiB encoded limit. A JSON value/container counts as one node; object member names count bytes but are not extra value nodes. Request root is depth0, rows1, row2, cell3, cell.value4. A json cell logically replaces its value-string node with the decoded JSON root at depth4 (do not count both); all expanded json cells share the same envelope node budget. Domain and both SDKs must use this identical accounting, including near-boundary cross-language fixtures. Preflight counts/nodes/text before expensive marshal/deep clone; no format-by-fmt.Sprint fallback. Defensive snapshot before asynchronous work. Oversize/malformed data fails as a whole, never silently truncates or reexecutes to fetch more data. selected/page only means what is materialized, including a previously truncated preview.

## Render wire and SDK

Args `{protocolVersion:1,exporterId,columns,rows}`. exporterId must match private selected declaration. Full encoded request <=512KiB; not just rows before adding envelope. Existing RPC frame cap remains1MiB.

Reply `{protocolVersion:1,rowCount:int,text:string}`; rowCount equals input snapshot count, UTF-8 text with no literal NUL, full encoded reply<=512KiB and decoded text<=512KiB. Nonzero input rows require nonempty text; zero rows may produce an empty document. Exact schema and required fields; unknown fields, aliases, duplicate keys, null, invalid numbers/Unicode, bad rowCount and excessive size fail before file creation. The plugin never returns a filename/path/URL or controls overwrite/opening. Metadata extension/contentType remains pinned to package digest. Host errors are safe fixed codes/localized messages, not raw backend diagnostics/data.

Go/TypeScript SDK provide an independent bounded exporter dispatcher with <=8 exporterId->Render handlers. Single request context is correct here (unlike long-lived AI sessions); generator returns text, SDK forms rowCount/protocolVersion and validates full output before replying. Catch/sanitize failures, honor cancel, no unsolicited stdout, no global registration or new dependencies. SDK metadata DTO files are owned separately from implementation helpers. Add a real independently built Typed NDJSON exporter example, no network/host-internal imports. Each line is an object in selected column order, with each column mapped to {kind,value?}. Number values are embedded as their original raw JSON numeric lexeme, boolean as native bool, json as strict raw JSON, string/binary as JSON string, missing/null as distinct kind-only objects. This explicit typed format avoids binary/string/json collisions and preserves numeric digits and missing/null distinctions; do not advertise it as ordinary untagged row NDJSON.

## Host-owned destination, cancellation and commit

Order: validate policy/pin/options/input and snapshot; strict register job; host save picker; recheck cancellation/root/pin; render; validate result; create a uniquely named same-directory .part via the existing atomic target; write; Sync/Close; final guard; atomic replace. No part/target is written for malformed/failed plugin results. No automatic opening of exported content. No destination or staging path is sent to plugin.

Plugin-only strict task registration derives from App/RPC lifecycle context, rejects duplicate existing JobID and caps simultaneous strict tasks at4. Require a bounded canonical nonempty JobID from UI runner (do not trim malformed IDs silently). Legacy registration must not replace an active strict task; if its registration is refused it gets a canceled context, never Background execution. Otherwise builtin duplicate/background semantics stay unchanged. Caller cancellation and app/root shutdown propagate; no claim that cancel can close an OS save dialog. Check again when picker returns. Reuse existing export:progress start/finalizing/done/error; streaming progress advances only after a whole chunk is durably written, never per row and never fabricated.

Host derives suffix/filter solely from declared extension. Preserve existing protection: if automatic suffix addition changes the chosen target and the resulting file exists, reject until the user explicitly chooses/confirms that actual target. Deny destination anywhere inside application config storage using the existing canonical protected-path guard (including symlink ancestors); check before work and before replace. No claims of an OS sandbox or protection against malicious same-user code.

Extend atomicExportTarget with an optional beforeReplace guard (after Sync/Close, before atomicReplace); old commit delegates nil guard and retains behavior. Guard checks ctx, current App data root, same manager/owner, digest/gen/permission/dependencies. Do not hold runtime locks while invoking filesystem operations. Record replaceAttempted only when entering atomic replace. Before that point, cancel/guard/write/sync/close failure leaves old target untouched and removes part. Once replace was attempted, any error is conservatively `outcomeUnknown:true` with a localized inspect-destination message; Unix directory-sync can fail AFTER rename, so never claim rollback, delete target or auto-retry. Successful commit returns success even if cancel/disable happens later; existing classifyExportTaskResult already preserves Success. The plugin-only final classifier must ALSO preserve outcomeUnknown even when ctx became canceled; never relabel a possibly published file as simple cancellation. This is an observable precommit fence, not an OS-atomic lock shared with arbitrary external controllers.

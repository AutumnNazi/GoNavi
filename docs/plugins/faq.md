# 插件作者 FAQ

本页回答第三方作者在开发、打包和上架 GoNavi 插件时最常见的问题。需要完整逐步流程时，先读[第三方插件作者指南](<author-guide.md>)。

## 文档与入口

### 应该先看哪篇文档？

按这个顺序：

1. [第三方插件作者指南](<author-guide.md>)：从零到上架的完整路径。
2. [开发指南](<development.md>)：SDK、打包、CLI 检查、安装和故障夹具。
3. [SDK](<sdk.md>) / [协议](<protocol.md>)：写代码和自定义 UI 时查阅。
4. 你选择的贡献类型专项文档。
5. 发布前看[权限参考](<permissions.md>)；出错看[故障排查](<troubleshooting.md>)。

`docs/plugins/README.md` 主要记录实现与验证状态，不是第一次开发的教程。网站顶栏“开发者文档”是概览入口，页脚“插件文档”打开 GitHub 文档目录；两者内容不同，但都属于同一文档体系。

### 网站“开发者文档”和页脚“插件文档”是同一份吗？

不是。顶栏进入市场站内的概览页，页脚进入 GoNavi 主仓的 `docs/plugins/` 目录。站内页适合先了解能力与流程，主仓文档才是完整契约和更新的权威来源。

## 开发与清单

### 必须用 Go 写插件吗？

Go SDK 和示例最完整，适合原生后端。仓库同时提供 TypeScript SDK/类型辅助；最终插件需要以宿主支持的声明式 UI、页面或原生进程形式接入。不要假设任意 Web 工程可以直接被市场安装。

### 插件 ID 怎么取？

使用发布者命名空间加英文句点，例如登录 GitHub 账号 `octocat` 后通常是 `gh-octocat.demo`。以网站“我的插件”显示的实际命名空间为准；命名空间不匹配时预检会返回 `canPublish:false`。

### 版本号可以用 `v1.0.0` 吗？

清单 `version` 使用标准 semver，不带 `v` 前缀；Tag 可以叫 `v1.0.0` 或 `plugin-name-v1.0.0`。市场判断版本的是包内 manifest 的 `version`。

### 可以提交源码目录吗？

不要。市场需要包含成品平台二进制、`gonavi.plugin.json` 和运行资源的插件包。源码树的 `backend.default` 不是成品清单，`check` 会拒绝。

### 一个包能支持哪些平台？

清单按 `backend.platforms` 声明，例如 `darwin/arm64`、`windows/amd64`。只声明实际构建并测试过的平台；没有声明的平台用户不会拿到错误的二进制。

### 可以带自定义 UI 页面吗？

可以，但要按页面契约实现：

- 主窗口声明式面板：无需完整前端工程，适合简单操作；
- 独立自定义窗口：需要完整 Wails/Web UI 时使用；
- `pages` + `navigation` + `ui.pages`：把页面挂到标题栏菜单；
- HTML 页面还需 `ui.html-panel`，并在沙箱和 CSP 限制内工作。

见[SDK 的 UI 选择](<sdk.md#ui-choices>)与[页面契约](<pages.md>)。

### AI 供应商插件需要模型代码吗？

不需要内置模型；你需要实现宿主声明的原生流式协议，向用户明确选择的上游端点转发请求，并正确处理取消、工具调用和错误。先看 [AI Provider 指南](<ai-providers.md>) 和 [SDK 示例](<../../examples/plugins/ai-provider/main.go>)。

### 权限可以“先申请多一点”吗？

不建议。权限是用户可见的安全边界，最小化申请；未实现的权限不应声明。数据源、AI Provider、导出等保留命令不能通过通用命令调用绕过宿主专属网关。

## 打包与检查

### `plugin check` 报 `declared entry is not a regular package file` 怎么办？

说明你检查的是源码清单，而不是成品包。先运行打包器生成 `backend.platforms` 和实际二进制，再检查输出目录或 ZIP。

### 为什么本地能运行，`check` 还是失败？

本地直接运行源码不等于市场包有效。常见原因：清单仍在源码模板状态、声明平台缺少二进制、路径不是包内相对路径、归档中有不允许的链接或额外目录。

### ZIP 根目录可以有外层文件夹吗？

不可以。`gonavi.plugin.json` 必须在压缩包根目录，`backend.platforms` 中声明的路径也从根目录解析。

### 应该提交多大包？

当前单包上限为 64 MiB；实际还要遵循清单、单文件、展开体积和条目数量限制。优先剔除缓存和不必要的调试产物，不要把多平台安装器塞入插件包。

## 发布到市场

### 只填 GitHub 链接就能发布吗？

**单插件仓库：可以。** 填仓库根链接，市场读取 latest stable Release 的唯一归档并预检。**一仓多插件：不行。** 必须填具体 Release/Tag 或 Release 资产链接，避免发布错插件。

### 官方 `Syngnat/GoNavi-Plugin-Market` 为什么不能只填仓库根？

它是官方插件 monorepo，同一个 latest Release 可能属于另一个插件。市场会返回 `release_required`，要求具体 Release/Tag；这是有意的安全约束，不是账号问题。

### GitHub Release 里放源码 ZIP 行不行？

不行。Release 中需要的是构建好的插件归档，根含 `gonavi.plugin.json` 和声明的二进制/资源。GitHub 自动生成的 Source code (zip) 不能直接作为市场插件包。

### 一个 Release 能放多个插件 ZIP 吗？

本插件发布路径需要明确的唯一归档。一个 Release 放多个插件文件会让市场无法判断发布谁；应为每个插件发布明确 Tag/Release，或让对应 Tag 的 Release 只包含该插件归档。monorepo 更应使用具体 Release 链接。

### 上传包和 GitHub Release 发布是什么关系？

GitHub Release 直发是首选：作者只需提供链接，市场读取并校验 Release 归档。上传 ZIP/TGZ 是离线包、私有仓库或 Release 暂时不可用时的兜底；两种路径共用同一套静态检查和版本状态机。

### 上架需要人工审核吗？

普通社区插件在静态预检通过后自助上架，不需要等待管理员逐版本批准。官方徽标单独由运营方授予。管理员仍可在事后下架违规版本；发布字节不可替换。

### 发布后还能改同一个版本吗？

不能。上架版本的字节和版本身份不可替换。修复问题需要提升 manifest 版本并发布新版本；被拒绝或下架的版本也不会自动恢复。

### 发布后来源没有登记怎么办？

如果响应含 `warning:"source_update_failed"`，说明插件已上架但自动更新来源未完成。到账号的插件页重试保存来源。官方 monorepo 不会把仓库根登记为后台 latest 来源，这是为了避免同步错插件。

## 安装、验证与更新

### 市场显示“已上架”就算完成了吗？

不算。还需要在干净环境完成市场安装、预览权限/摘要、启用并实际调用一次。静态校验不能证明二进制逻辑、平台兼容、模型端点或外部账号可用。

### 怎么验证 SHA-256？

预检页会显示归档摘要。用 `shasum -a 256` 或 PowerShell `Get-FileHash -Algorithm SHA256` 核对本地 ZIP；市场下载后的 artifact 摘要应与预检一致。

### 更新插件需要先卸载吗？

不需要。已安装插件从市场更新会走替换并保留启用意图；替换失败时仍保留原包。不要绕过市场的摘要与版本检查手工覆盖已发布字节。

### 为什么本地启用成功但调用失败？

启用只持久化意图。可能仍在启动、已进入故障/隔离，或依赖缺失；查看状态与 `lastError`，修复后重新启用。超时或崩溃的写操作不要盲目重试。

## 安全与责任

### 市场会执行插件来做安全审计吗？

不会。检查和安装预览只做静态校验；测试 Provider 等显式动作可能发起网络请求，但不会代替代码审计。插件以当前用户权限运行，必须自行处理密钥、网络、文件和第三方依赖风险。

### 作者能看到用户凭据吗？

只能收到宿主显式投影给该次调用的字段。不要记录密钥、完整请求、上游错误正文或用户业务数据；AI Provider 只应拿到用户选择的那条配置。

### 发现插件有严重问题怎么办？

立即停止建议用户使用，发布修复版本并联系市场运营；管理员可以 yank 已发布版本。不要尝试替换已发布字节或伪造相同版本。
